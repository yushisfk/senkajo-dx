# 既存kintoneアプリ関係図（As-Is）

## 0. 本書の位置づけ

既存kintone環境（現行本番）の現状（As-Is）を記録する。設計・改善案は含めない。

- 既存本番アプリは改修しない方針である。
- V2の方針・構成は本書ではなく、[BASIC_ARCHITECTURE.md](../00_project/BASIC_ARCHITECTURE.md) 第I部を参照する。

### 表記

- **【確認済】**：上記資料から直接確認した事実
- **【業務確認済】**：資料外で、業務担当者への確認により確定した事実
- **【推定】**：資料からの推測。未確定
- **【未取得】**：資料がなく不明

### テンプレートに含まれないもの

テンプレートはアプリ定義のみを含む。以下は含まれない。

- 実環境のアプリID（数値）
- ドメイン
- マスタのレコードデータ
- 運用中のアクセス権設定

テンプレート上のACLはすべてのアプリで空だった。ただし、テンプレートは権限を引き継がない仕様の可能性があり、実環境の権限は【未取得】。

    - ルックアップ・サブテーブルなし。
    - 一覧は「（すべて）」1本のみ。グラフなし。

    - コンテナサイズは20が8件、30が3件、空欄1件。

## 2. ルックアップ関係【確認済】

```
受注管理（選果場出荷物）
 ├─ 商品名 ──lookup──▶ 青果物商品マスタ（出荷・在庫用）.商品名
 └─ 出荷先 ──lookup──▶ 青果物出荷先マスタ.出荷先名
                          └─ 得意先名 ──lookup──▶ 顧客情報.得意先名

受注管理（産直出荷物）
 ├─ 商品名 ──lookup──▶ 青果物商品マスタ（出荷・在庫用）.商品名   （コピー項目なし）
 └─ 出荷先 ──lookup──▶ 青果物出荷先マスタ.出荷先名              （得意先のみコピー）

なす生産者リスト ── ルックアップ・関連レコード一覧なし（他アプリを参照しない）
（2つの受注管理テンプレートにも、生産者マスタを参照するルックアップ・関連レコード一覧は存在しない。
  調査対象外のアプリからの参照の有無は【未取得】）
```

2つの受注管理が参照するマスタは、同じ本番アプリと【推定】。
- 根拠：両テンプレートで、マスタのフィールドIDと定義が一致している（商品マスタは、後から追加された「選果場DX対象」を除く）。
- テンプレートからは実アプリIDを確認できない。

### ルックアップ一覧

| 参照元アプリ | 参照元フィールド（コード） | 参照先アプリ | キー（参照先フィールド） | コピーされる項目（参照先 → 参照元） |
|---|---|---|---|---|
| 受注管理（選果場出荷物） | 商品名（`ルックアップ_0`） | 青果物商品マスタ | 商品名（`文字列__1行_`） | Lot番号 → 商品Lot<br>品名１（佐川） → 品名１（佐川ヤマト共用）<br>使用資材（ラベル袋） → 使用資材<br>資材使用量 → 資材使用量（c/s） |
| 受注管理（選果場出荷物） | 出荷先（`ルックアップ`） | 青果物出荷先マスタ | 出荷先名（`出荷先名`） | 得意先名 → 得意先<br>住所録コード・依頼主コード（佐川用）<br>お届け先名・住所・郵便番号・会社部門１・電話番号<br>ご依頼主名・住所・郵便番号・電話番号 |
| 受注管理（産直出荷物） | 商品名（`ルックアップ_0`） | 青果物商品マスタ | 商品名（`文字列__1行_`） | なし（キーのみ） |
| 受注管理（産直出荷物） | 出荷先（`ルックアップ`） | 青果物出荷先マスタ | 出荷先名（`出荷先名`） | 得意先名 → 得意先 |
| 青果物出荷先マスタ | 得意先名（`ルックアップ_0`） | 顧客情報 | 得意先名（`文字列__1行_`） | なし（キーのみ） |

- **ルックアップのキーはすべて名称文字列**である。商品名・出荷先名・得意先名は、いずれも参照先で「値の重複を禁止」になっている。
- ルックアップはコピー型である。マスタ側を変更しても、既存の受注レコードは自動では更新されない（kintone標準仕様）。
- 2つの受注管理とも、「関連レコード一覧」フィールドはない。
- 2つの受注管理では、同じフィールドコードが別の意味で使われている（例：`ラジオボタン_0` は選果場側で「出荷」、産直側で「発注」）。詳細は DIRECT_SHIPPING_ORDER_APP_AS_IS.md §6。

## 3. 何をSource of Truthとしているか（As-Is）

| 情報 | 現在の保持場所 | 備考 |
|---|---|---|
| 商品情報（商品名・規格・送り状品名・使用資材） | 青果物商品マスタ | 受注（選果場出荷物）へは登録時点の値がコピーされる |
| **商品Lot** | **青果物商品マスタ内のフィールド「Lot番号」**（`数値`、数値型） | **独立した「商品Lotマスタ」アプリは存在しない**。<br>受注管理（選果場出荷物）の「商品Lot」はルックアップでコピーされた値。受注管理（産直出荷物）には商品Lotフィールドがない |
| 選果場DX対象 | 青果物商品マスタ「選果場DX対象」（`senkajo_dx_target`） | ユーザーが意図的に追加した項目（PRODUCT_MASTER_AS_IS.md §2.1） |
| 出荷先情報・送り状用住所・コード | 青果物出荷先マスタ | 受注（選果場出荷物）へコピーされる |
| 得意先情報 | 顧客情報 | 出荷先マスタ経由で、両受注管理の「得意先」にコピーされる |
| 生産者情報 | なす生産者リスト | 生産者氏名（重複禁止）、生産者番号等。<br>「生産者番号」が出荷lotの「生産者Lot」と同一かは未確認（PRODUCER_MASTER_AS_IS.md §6） |
| 受注・出荷予定数量 | 受注管理（選果場出荷物）、受注管理（産直出荷物） | 出荷物の種類によって2アプリに分かれている |
| 出荷状態・出荷lot | 受注管理（選果場出荷物）の「出荷」「出荷lot」 | 詳細は ORDER_APP_AS_IS.md |
| 産直の状態項目 | 受注管理（産直出荷物）の「発注」「出荷確認」 | どちらも現在の実運用では使われていない【業務確認済】。詳細は DIRECT_SHIPPING_ORDER_APP_AS_IS.md §5 |
| 送り状データ | 受注管理（選果場出荷物）からJSでファイル出力 | 送り状番号を保持するフィールドは、どちらの受注管理にもない。産直側には送り状出力機能がない |
| 販売管理・売上・集計 | FLAM（kintone外） | 受注はkintoneへ入力後、FLAMへ再入力している【業務確認済】 |
| 仕切り実績・在庫 | kintone上に該当アプリなし（今回の資料の範囲） | 現状は紙運用 |
